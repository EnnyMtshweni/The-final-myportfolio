CASE STUDY

Global Layoffs Analysis (2020–2023)

Cleaning a messy, real-world dataset in SQL, then turning it into dashboards that actually answer a question.

  • SQL
  • Power BI
  • Tableau
  • Python
View Live Demo View Repo

// the_problem

The raw layoffs dataset covering 2020–2023 was exactly what real-world data usually looks like: duplicate rows, inconsistent date formats, blank fields standing in for nulls, and company/industry names spelled several different ways. In that state, it couldn't answer even a simple question like "which industry was hit hardest, and when."

// the_approach

I worked the dataset through SQL in stages rather than editing the raw table directly, so every transformation stayed traceable and reversible:

  • Staging: copied the raw data into a staging table before touching anything, so the original import was never overwritten.
  • Cleaning: removed duplicate rows, standardised inconsistent text (company and industry naming), and converted dates into a proper date type.
  • Handling nulls: identified where blanks should be nulls versus genuine zeros, and backfilled a few fields using related rows where it was safe to do so.
  • Exploration: wrote queries to find the largest layoffs by company, industry, country, and year, and to track the trend over time.
  • Visualisation: brought the cleaned data into Power BI and Tableau to build dashboards a non-SQL audience could actually read.

// the_impact

This project was less about a single headline number and more about the full pipeline — going from a genuinely messy CSV to a dataset I'd trust an actual business decision on, and then presenting it in a way someone outside data could interpret in under a minute.
